# 阶段四：数据开发（4-6 周，生产实战版）

目标：写出**幂等、可重跑、有数据质量校验**的管道，而不是"一次性脚本能出结果"。

## 课程安排

### 第一周：数据分析基础（生产习惯）

| 天 | 主题 | 生产要点 |
|----|------|----------|
| 1 | NumPy：向量化思维 | 循环换向量化，性能差 10-100 倍 |
| 2 | Pandas：DataFrame、选择、过滤 | 链式操作副本 vs 视图；SettingWithCopyWarning |
| 3 | Pandas：分组聚合、透视表 | 分组逻辑先小样本验证再全量跑 |
| 4 | 数据清洗：缺失值、重复、类型转换 | **清洗规则要显式**：丢弃多少行、为什么丢，都要记日志 |
| 5 | 可视化：Matplotlib / Seaborn | 图是给人看结论的，坐标轴、单位、标题齐全 |

### 第二周：SQL 与数据库进阶

| 天 | 主题 | 生产要点 |
|----|------|----------|
| 6 | SQL 进阶：JOIN 类型、子查询 vs JOIN | LEFT JOIN 产生笛卡尔积的坑；重复行检查 |
| 7 | 窗口函数：ROW_NUMBER / RANK / LAG | 去重取最新、TopN、环比同比的标准武器 |
| 8 | CTE 与执行计划 | 复杂查询拆 CTE 可读；EXPLAIN 定位慢点 |
| 9 | 索引与分区分表 | 大表设计：分区键选择、查询裁剪 |
| 10 | Python 连库与数据写入 | 批量写入（executemany / COPY）；逐行 insert 是灾难 |

### 第三周：ETL 工程化（重点）

| 天 | 主题 | 生产要点 |
|----|------|----------|
| 11 | ETL 设计：抽取-转换-加载分层 | 每层职责单一，转换逻辑可单独测试 |
| 12 | 幂等与增量：断点续传 | 任务重跑结果一致（upsert / 先删后插 / 事务回滚） |
| 13 | 数据质量：校验规则、行数核对 | 空值率、主键唯一、外键核对、行数对账；异常阻断并告警 |
| 14 | 失败处理：重试、告警、数据回补 | 部分成功怎么办；保留中间态便于回补 |
| 15 | 大文件与内存优化 | 流式读取（chunksize）；dtypes 优化内存占用 50%+ |

### 第四周：调度与项目

| 天 | 主题 | 生产要点 |
|----|------|----------|
| 16 | 调度框架：Prefect 入门（比 Airflow 轻） | 任务依赖、定时、失败重试策略 |
| 17 | Airflow 概念（了解即可） | DAG 设计；调度与数据依赖的区别 |
| 18-19 | 项目：定时数据同步管道 | 从源库抽数 → 清洗校验 → 入仓，失败可重跑 |
| 20 | 项目收尾：监控告警、文档 | 任务成功/失败告警；README 写清数据流图 |

## 生产习惯清单（本阶段验收标准）

1. 任务跑一半挂了，重新跑一遍不会产生重复数据（幂等）
2. 每次运行输出：处理行数、成功/失败/跳过数量
3. 脏数据有明确处理规则并记录，不是悄悄丢弃
4. 大表操作先小样本验证，再全量执行
5. 写库用批量操作，不用逐行 insert
6. 有告警：任务失败、数据量突降、对账不平都会通知到人
